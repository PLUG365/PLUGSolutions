# PLUG Solutions 掲載申請フォーム仕様 v1

## 目的と境界

- 作者本人から、公開カタログへ掲載するための情報だけを受け付ける。
- Microsoft Forms は「誰でも回答可能」にし、Microsoft アカウントへのサインインを要求しない。
- Forms が回答者の氏名やメールを自動取得しない設定にする。
- 公開用の表示名と X アカウントは入力を求めるため、完全な匿名投稿ではない。サイトでは「サインイン不要」と表記する。
- 本名、メールアドレス、会社名、所属、住所、電話番号、ユーザー ID、ファイルは収集しない。
- 機密情報、個人情報、顧客データを入力しないようフォーム冒頭と自由記述欄に表示する。
- 回答だけで自動掲載しない。SharePoint への転記、人による審査、公開 JSON の確認、Pull Request、本番リリースを必須とする。

## Forms 設定

| 設定 | 値 |
| --- | --- |
| フォーム名 | PLUG Solutions 掲載申請 |
| 回答者 | 誰でも回答可能 |
| サインイン | 不要 |
| 回答受付 | 有効 |
| 質問のシャッフル | 無効 |
| 開始・終了日時 | 初期は設定しない |
| ファイルアップロード | 使用しない |
| 回答のコピー送信 | 使用しない |
| 回答ごとのメール通知 | 運営者が必要と判断した場合のみ。回答内容や送信者メールを外部へ転送しない |

「1 人 1 回」の制限はサインインを必要とするため使用しない。重複や荒らしは審査で除外する。

## 冒頭表示

> 作者本人からの申請だけを受け付けます。氏名・メール・会社名は収集しません。公開用の表示名と X アカウント、作品情報は掲載時に公開されます。個人情報、顧客情報、社内 URL、API キーなどの秘密情報を入力しないでください。申請は掲載を保証するものではありません。

## 設問

設問 ID は Power Automate と SharePoint の対応付けで使用するため、作成後に意味を変更しない。

## 送信完了メッセージ

> 申請ありがとうございます。内容、公開 URL、作者情報、ライセンス、導入条件、画像の権利を人が確認します。申請は掲載を保証するものではありません。確認が必要な場合は、記載された公開 X アカウントへ PLUG Solutions 運営者から連絡します。

## SharePoint 転記と非公開項目

- Forms の Response ID を一意キーとして SharePoint に保存し、Power Automate の再試行で重複作成しない。
- `C01`〜`C04`、`I01`、`I02`、`R01`、`R02`、Response ID、回答日時、審査状態、審査メモは非公開とする。
- 公開 JSON は `P01`〜`P15` の承認済み情報から生成し、人が slug、正規化した URL、ローカルサムネイル、公開日、更新日を追加する。
- 回答にメール、氏名、秘密情報などの禁止情報が含まれていた場合は公開 JSON へ転記せず、審査状態を「要確認」または「却下」にする。

## サイト接続

1. Forms を作成し、「誰でも回答可能」でサインイン不要になることをシークレットウィンドウで確認する。
2. 回答用 URL を GitHub の `production` Environment variable `NEXT_PUBLIC_SUBMISSION_FORM_URL` に保存する。URL は公開情報なので Secret に保存しない。
3. デプロイワークフローで同名の環境変数を静的ビルドへ渡す。
4. 手動本番リリースを実行し、サイトの「サインイン不要のフォームから掲載申請」から Forms が開くことを確認する。
5. Forms URL が未設定または不正な場合は、サイトを「掲載フォーム準備中」のままにする。

## 公開前の人手確認

- シークレットウィンドウで Microsoft アカウントへのサインインを要求されない。
- 回答者の氏名とメールが Forms の回答列に自動追加されない。
- すべての必須同意が「はい」にならなければ受理しない。
- ファイルアップロード欄がない。
- フォーム本文、選択肢、完了メッセージに個人メールアドレスやテナント内部 URL がない。
- テスト回答を削除する前に Power Automate と SharePoint の重複防止を確認する。
